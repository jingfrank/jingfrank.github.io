## 一、背景演进：从 VLM 语义推理到 FastAD 毫秒级单类初筛

在前两篇文章中，我们探讨了如何使用 **Qwen3-VL** 多模态大模型进行受电弓开集异物识别与 vLLM 加速。然而在动车组实际车载运行（350 km/h）中，弓网安全监控面临严苛的硬实时指标要求：

1. **正样本极端匮乏**：真实运行中，恶性大火花放电、受电弓框架变形扭曲、绝缘子破损或悬挂异物属于千载难逢的极端低概率事件。传统的有监督目标检测（如 YOLO）需要数千张高质量缺陷标注切片，在实际落地时几乎无法获取完备的缺陷集；
2. **逐帧检测的实时算力瓶颈**：车载 1080P/4K 工业相机输出为 20~25 FPS。即便利经极致优化，参数量在数个 B 的视觉语言大模型（VLM）单次推理仍需 1 秒左右，只适合作为“低频复核网关”，无法承担 20~25 FPS 的全量逐帧初筛；
3. **闭集检测器的盲区**：塑料薄膜、编织袋碎片、鸟巢、断落金属丝等开集异物形态各异，传统闭集检测器极易漏检未定义的目标类别。

![FastAD 与空间-时序解耦状态机流水线](/images/blog/fastad-decoupling-pipeline.svg)
*图 1：从底层的 FastAD 45ms 极速异常感知，到上层 fault_classifier 确定性物理归因流水线*

基于这一现状，我们引入了基于单类学习（One-Class Learning）的视觉异常检测范式——**FastAD (Fast Anomaly Detection)**。它彻底打破了对缺陷样本的依赖，仅学习受电弓“正常工况”下的流形分布，并能在边缘端输出高达 **45~50 ms/帧** 的极速无监督异常响应。

## 二、FastAD 工业级轻量化建模机制

### 1. 8:2 分层基准库与零缺陷冷启动

FastAD 的核心理念是**“只认常态，偏离即异动”**。训练过程中，模型完全不需要接触任何标注了“火花”、“脏污”或“异物”的缺陷图片。

我们从 4 个不同运行车次、不同光照工况（强光、逆光、夜间、阴天）的受电弓监控视频中，截取了 500 帧处于绝对纯净平稳运行的正常帧，构建了 **8:2 分层基准数据集**：

```
dataset/
├── train/        # 训练集：400 帧（各视频按模 5 轮转抽取 80%，学习纯净几何分布）
└── val/          # 验证集：100 帧（各视频对称抽取 20%，用于自适应标定阈值）
```

通过这种分层抽样，模型构建的多元特征高斯分布能够天然抵御车体抖动、接触网张力摆动与外界光照变化的常态漂移。

### 2. 浅层几何特征抽取（Layer 2 vs Layer 3）

在特征提取主干（Backbone）的选择上，我们选用了具有强大表征能力的 `wide_resnet50_2`。但在抽取层级的实验中，我们发现了浅层与深层特征在工业几何监测中的关键差异：

| 特征抽取层级 | 空间特征图分辨率 | 感知野与语义偏向 | 边缘缺陷敏感度 | 单帧推理耗时 |
| :--- | :--- | :--- | :--- | :--- |
| **Layer 3 (深层)** | 16 × 16 | 大感受野，偏向高级语义抽象 | 对微小异物边缘、滑板局部微小拉弧钝化 | ~68 ms |
| **Layer 2 (浅层)** | **32 × 32** | **局部高分辨率几何轮廓与纹理** | **对滑板边缘畸变、细线异物反应极其敏锐** | **~45 ms** |

实验表明，受电弓监测本质是**严格刚性几何部件与其接触环境的物理轮廓变化**。Layer 2 在保留高频空间几何细节的同时，大幅降低了特征维度与通道数，单帧计算时间稳定在 45 ms 左右，为车载实时流水线预留了充裕的 CPU/GPU 裕量。

### 3. Ledoit-Wolf 协方差收缩与自适应门限标定

在提取特征 Patch 并计算局部与全局马氏距离（Mahalanobis Distance）时，高维特征样本协方差矩阵容易出现病态或不可逆。FastAD 采用 **Ledoit-Wolf 收缩估计器（Ledoit-Wolf Shrinkage）**，在经验协方差矩阵与单位阵之间进行解析最优加权，确保逆协方差矩阵的高效稳定数值解：

$$\Sigma_{\text{LW}} = (1 - \rho)\Sigma_{\text{emp}} + \rho \nu I$$

随后，模型在 100 帧独立验证集上计算正态分位数（Quantile CDF），自动拟合并固化出无偏门限：
* **自适应图像级异常门限（Image Threshold）**：标定值为 `4.20`（高于此分值意味着全图特征出现整体分布漂移）；
* **自适应像素级异常门限（Pixel Threshold）**：标定值为 `2.96`（高于此分值的像素块被判定为局部几何畸变点）。

## 三、核心技术边界：异常检测（AD）与故障分类（Classifier）的语义鸿沟

在算法研发初期，很多人容易对“无监督异常检测”产生一种过度理想化的预期，认为热力图上一亮，就等于找到了具体的缺陷。

但在动车组车载控制系统中，底层硬件与列车司机需要的是**具有明确操作规程的确定性业务故障代码**：
* 触发 `0x03 大火花`：需要评估是否瞬态降弓防烧网；
* 触发 `0x0A 画面脏污`：属于车载传感器故障，需提示机务段清洗镜头，而不是下发列车紧急制动；
* 触发 `0x0E 悬挂异物`：需提示前方路段可能存在外界漂浮物缠绕；
* 触发 `0x04 结构异常`：属于重大机械结构损伤，必须立即降速检查。

**FastAD 本质是一个“检测器（Detector）”，而非“分类器（Classifier）”**：
1. **它输出的是连续分布，没有语义标签**：它只能输出一张浮点型热力图（Anomaly Map）和一个标量异常分（Score），告诉你“这里跟基准模型不一样”，但它根本不知道“这是火花还是油污”；
2. **多物理源的能量交叉耦合**：
   * **大火花光斑的能量泛化**：接触网与碳滑板放电时会产生强烈的白炽电弧光晕。这片几十万像素的高亮异常不仅抬高了滑板处的异常分，还会通过主干网络卷积扩散，导致受电弓金属框架处的异常分同时被动超标；
   * **镜头脏污的单帧伪装**：粘在镜头表面的一滴雾状油污或水渍，在单张画面上看，就是一个局部的暗色畸变斑块。从静态单帧来看，它与受电弓框架变形在数学特征上具有极高的相似度；
   * **环境复杂背景的分布偏移**：当动车组以 350 km/h 驶入火车站台或穿越大型钢架桥梁时，车顶上方密集交织的雨棚钢桁架迅速掠过。这些复杂的几何背景在无监督模型眼中全是“基准分布外”的特征，会瞬间激发出大量细碎的连通域轮廓；
   * **车顶大灯的反光干扰**：车顶夜间高强度探照灯直接照射在抛光的碳滑板接触面上，产生强烈的镜面高光，常常导致静态异常分升高。

正因如此，直接拿 FastAD 的热力图去报故障是行不通的。我们必须在其之上构建一层具备**领域物理先验与时空解耦能力的状态机引擎——`PantographFaultClassifier`**。

## 四、深度拆解：PantographFaultClassifier 空间-时序解耦状态机

针对上述物理特性的交织，我们编写了独立高效的解耦引擎 [`fault_classifier.py`](file:///home/ibd/jyb/gongwang_fastad/fastad_detector/fault_classifier.py)。这套引擎不增加重度深度学习计算量，全部基于 OpenCV、NumPy 与纯物理特征状态机实现，执行耗时小于 **1.5 ms**。

### 1. 空间 ROI 切片与环境背景屏蔽

受电弓各机械部件在安装相机中的投影具有高度稳定的几何拓扑结构。我们将整张画面解耦为三个专属的物理交互区，并屏蔽干扰死区：

```python
# 1. 大火花监测专区：碳滑板与接触线相互摩擦碰撞的狭长条带
slide_roi_ratio = (0.25, 0.25, 0.75, 0.48)

# 2. 悬挂异物监测专区：碳滑板上方及羊角两侧的悬挂空间
catenary_roi_ratio = (0.25, 0.25, 0.85, 0.50)

# 3. 受电弓结构监测专区：下导杆、上导杆与双臂铰链工作区（排除滑板高压接触区）
pantograph_roi_ratio = (0.15, 0.32, 0.85, 0.88)
```

> **📌 关键细节：屏蔽底部 OSD 水印与车顶死区**  
> 车载视频流底部往往叠加有动态跳变的车速、时间戳、车次号等 OSD 字符（`y > 0.82`）。我们在任何故障检测前直接将 `y > 0.82` 划入计算掩码之外，防止字符跳变被统计为镜头脏污或结构畸变。

### 2. 大火花：多物理特征联合熔断判据

常态下车顶探照灯会在碳滑板形成静态反光；而镜头附着脏污时全图异常分也会爆表。若仅靠单一的“亮度高”或“异常分高”，就会引发高频误报。

我们设计了**“过饱和像素规模 + 局部灰度均值 + 饱和区特征偏离度”**的三重物理联合判据：

```python
# 提取滑板专属 ROI 区域
slide_gray = gray[ry1:ry2, rx1:rx2]
slide_anom = anomaly_map[ry1:ry2, rx1:rx2]

sat_mask = slide_gray >= self.spark_brightness_threshold  # 亮度阈值 245
sat_pixel_count = int(np.sum(sat_mask))
slide_mean_gray = float(np.mean(slide_gray))
sat_anom_mean = float(np.mean(slide_anom[sat_mask])) if sat_pixel_count > 0 else 0.0

# 真实大火花物理特征综合判据：
if img_anomaly_score >= (img_thresh * 0.95):
    if (
        # 条件 1：强电弧大面积白炽放电（饱和像素数 >= 60,000 且 灰度均值 >= 165.0 且 饱和区异常偏离 >= 1.8）
        (sat_pixel_count >= 60000 and slide_mean_gray >= 165.0 and sat_anom_mean >= 1.8)
        # 条件 2：局部剧烈聚焦放电电弧（饱和像素数 >= 30,000 且 饱和区异常均值 >= 2.5）
        or (sat_pixel_count >= self.spark_min_pixel_count and sat_anom_mean >= 2.5)
        # 条件 3：超高能强弧漫射（引入 >= 10000 饱和像素硬约束，杜绝镜头脏污的高异常分误触火花）
        or (sat_pixel_count >= 10000 and sat_anom_mean >= 3.5)
    ):
        spark_detected = True
```

**工程避坑点**：在条件 3 中，我们最初只写了 `sat_anom_mean >= 3.5`，结果在 `dirty_1.mp4`（雾状油污）测试中，由于油污导致整幅画面的异常分极高，滑板区域偶然有几十个白噪点就触发了条件 3。我们紧急补充了 `sat_pixel_count >= 10000` 的像素规模硬门槛，彻底解决了暗斑油污误报大火花的问题。

### 3. 画面脏污：相机坐标系 64×64 时序网格与 dirt_pending 观察态

画面脏污与机械故障的最大本质区别在于**参考坐标系**：
* 列车以 350 km/h 运行，外部接触网、异物、背景都在**世界坐标系**中以极高相对速度向后飞逝；
* 粘在镜头防护罩上的油渍、泥点、水渍，在**相机机体坐标系**中是静止固定的。

#### ① 64×64 降采样网格与 IIR 时序平滑
为了屏蔽车体震动带来的亚像素高频抖动，我们将全图异常特征图（剔除火花滑板区与底部水印区后）自适应降采样为 $64 \times 64$ 的低通网格，并执行时序一阶滞后滤波（IIR）：

```python
# 64x64 低通降采样
grid_anom = cv2.resize(dirt_anom_clean, (64, 64), interpolation=cv2.INTER_AREA)
grid_active = (grid_anom >= pix_thresh).astype(np.float32)

# 时序动量累积（当前帧占比 15%，历史记忆占比 85%）
self.dirt_grid_history = 0.85 * self.dirt_grid_history + 0.15 * grid_active
```

当且仅当网格在相机固定位置持续激活超过 4 帧（`dirt_persistence_frames = 4`）且激活单元数 $\ge 6$ 时，确诊为“画面脏污”。

#### ② 核心创新：引入 `dirt_pending` 观察态，阻断冷启动误报
在时序滤波器刚刚启动的第 1~3 帧，由于历史信息尚未收敛，此时如果镜头上正好有一大块油污，它在单帧中展现出极高的像素异常，但尚未满足持续 4 帧的持久化条件。

如果直接放行，该异常就会**向下穿透**，进入下方的结构异常检测模块，导致系统在刚开机的几秒内高呼“受电弓结构断裂”！

为此，我们设计了**脏污候选观察态（Pending State）**：

```python
# 在时序累积未满 4 帧的冷启动窗口中：
active_grid_count = int(np.sum(grid_active))
if (
    active_grid_count >= self.dirt_pending_cells_threshold  # 单帧异常网格激活数 >= 15
    and img_anomaly_score > (img_thresh * 0.90)
    and not spark_detected
):
    dirt_pending = True  # 标记为脏污观察态，就地冻结！
```

一旦标记为 `dirt_pending`，系统立即对下层的“受电弓结构异常”与“悬挂异物”执行**硬熔断机制**，阻止任何穿透性虚警。这一精妙设计彻底根除了系统初始化阶段的结构误报。

### 4. 悬挂异物：密集桁架群聚过滤与连通域约束

在接触网悬挂区 `catenary_roi_ratio`，异物通常表现为孤立的悬挂斑块（面积大于 100 像素）。但在列车穿越铁路客站时，站台雨棚的钢结构网格会在接触网背景中产生十几甚至几十个密集的细碎连通域。

我们通过轮廓计数器实现**站台密集桁架群聚抑制**：

```python
f_contours, _ = cv2.findContours(foreign_bin, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)

# 密集站台雨棚抑制：如果瞬间并发出现的轮廓数超过 12 个，直接判定为站台密集建筑，拒绝误报异物！
if len(f_contours) <= self.max_blobs_filter:  # max_blobs_filter = 12
    for cnt in f_contours:
```

### 5. 故障优先级仲裁与置信兜底机制 (Confident Fallback)

在所有空间和物理特征计算完成后，系统执行严格的故障优先级决策树，并引入置信兜底逻辑：

```python
faults_found = []

# 1. 大火花放电：具备最高物理破坏力与瞬态强光属性，拥有绝对第一优先级！
if spark_detected:
    faults_found.append("大火花")

# 2. 画面脏污/观察态：相机传感器本体故障，阻断后续部件结构判断
elif dirt_detected:
    faults_found.append("画面脏污")
elif dirt_pending:
    faults_found.append("画面脏污(观察中)")

# 3. 受电弓结构异常：仅在无火花电弧且无镜头脏污遮挡时方可触发
elif structural_detected:
    faults_found.append("受电弓结构异常")

# 4. 悬挂异物：仅在无大火花且画面清晰无污染时方可触发
elif foreign_detected:
    faults_found.append("悬挂异物")

# 5. 置信兜底机制 (Confident Fallback)
# 只要没有具体物理拓扑证据 corroborated，哪怕全图异常分轻微超标，坚决回落为“正常”！
if faults_found:
    has_fault = True
    primary_fault = f"异常-{faults_found[0]}"
else:
    has_fault = False
    primary_fault = "正常"
```

这种设计体现了工业现场的核心安全原则：**“宁可信任具体的物理几何证据，绝不盲从模糊的统计学偏离分”**。

## 六、总结：工业视觉“轻量初筛 + 深度归因”的双层协同范式

通过这一阶段的工程探索，我们对工业场景下复杂视觉任务的架构分工有了更为清晰的认知：

```
[4K 车载视频流 20~25 FPS]
           │
           ▼
┌──────────────────────────────────────────────────────────┐
│  第一道防线：FastAD + 空间时序状态机 (车载边缘端，单帧 45ms) │
│  • 职责：全天候 20+ FPS 逐帧硬实时极速初筛                  │
│  • 优势：零缺陷样本训练、极低能耗、多物理先验熔断高频虚警      │
└──────────────────────────┬───────────────────────────────┘
                           │ 仅在触发高置信异常或疑点切片时
                           ▼
┌──────────────────────────────────────────────────────────┐
│  第二道防线：Qwen3-VL 视觉语言大模型 (微服务集群，单次 1s)    │
│  • 职责：开放词表深层语义归因、微小悬挂异物材质研判           │
│  • 优势：免微调开集语义泛化、多轮 CoT 逻辑校验、自动生成运维报告 │
└──────────────────────────────────────────────────────────┘
```

大模型不应被滥用来做高帧率的简单初筛，无监督小模型也不应被苛求去理解高阶开放语义。**让 FastAD 专注在 50ms 内感知“哪里偏离了常态”，让 `fault_classifier` 依据物理法则消除虚警并完成精准初筛，再让 VLM 大模型在疑难切片上释放开放语义的推理能力**——这才是工业智能视觉系统稳健落地的最优解。
